# Построение пайплайна данных на Spark, Airflow и Greenplum

## Контекст

Для аналитической системы требовалось организовать обработку данных из объектного хранилища, построить несколько отчётных витрин и сделать результаты доступными для SQL-запросов.

## Цель проекта

Создать единый пайплайн, который:

- читает исходные данные из S3;
- обрабатывает их в Spark на Kubernetes;
- сохраняет готовые отчёты в формате Parquet;
- создаёт внешние таблицы Greenplum через PXF;
- управляется и контролируется с помощью Apache Airflow.

## Стек

- Python
- PySpark
- Apache Airflow
- Kubernetes
- S3
- Greenplum
- PXF

## Архитектура

```text
S3 (raw data)
      |
      v
Spark on Kubernetes
      |
      v
S3 (Parquet reports)
      |
      v
Greenplum PXF external tables
```

Airflow запускает пять независимых веток:

```text
start -> Spark job -> sensor -> Greenplum table -> end
```

## Отчёты

Пайплайн формирует пять отчётов:

1. `lineitems_report` - показатели по позициям заказов.
2. `orders_report` - агрегаты заказов по месяцу, стране и приоритету.
3. `customers_report` - статистика клиентов по регионам и сегментам.
4. `suppliers_report` - статистика поставщиков по регионам и странам.
5. `parts_report` - показатели товаров и стоимости поставок.

## Этапы работы

1. Подготовил Spark-задачи для чтения и объединения исходных таблиц.
2. Реализовал группировки, агрегаты и расчёт показателей для пяти отчётов.
3. Настроил сохранение результатов в S3 в формате Parquet.
4. Подготовил конфигурации SparkApplication для запуска в Kubernetes.
5. Собрал Airflow DAG с параллельным выполнением независимых веток.
6. Настроил создание внешних таблиц Greenplum над файлами в S3 через PXF.
7. Проверил повторный запуск пайплайна и идемпотентное пересоздание витрин.

## Результат

- Пять отчётов строятся параллельно и сохраняются в S3.
- Airflow отслеживает завершение каждой Spark-задачи.
- Greenplum предоставляет единый SQL-интерфейс к результатам обработки.
- Повторный запуск не требует ручного удаления старых отчётов и таблиц.
- Весь процесс выполняется одним DAG.

## Структура проекта

```text

  data_pipeline.py

  common.py
  customers.py
  lineitems.py
  orders.py
  parts.py
  suppliers.py
k8s/
  customers.yaml

  orders.yaml
  parts.yaml

  suppliers.yaml
```

## Настройка

Секреты не хранятся в репозитории. Для локального запуска используются переменные окружения из `.env.example`, а в Kubernetes - Secret с именем `s3-credentials`.

Файл `k8s/s3-secret.example.yaml` содержит только шаблон. Перед применением необходимо создать собственный Secret и не добавлять его значения в Git.

В Airflow должны быть созданы подключения:

- `kubernetes_default` - Kubernetes;
- `greenplum_default` - Greenplum.
